# HTTP API Specification

| Field | Value |
| --- | --- |
| Base URL (local) | `http://localhost:8000` |
| API prefix | `/api/v1` |
| OpenAPI document | `/openapi.json` (generated by FastAPI from the live models) |
| Interactive docs | `/docs` (Swagger UI), `/redoc` |
| Content type | `application/json` unless stated otherwise |
| Authentication | **None** in this build. Do not expose the service to untrusted networks (see [THREAT_MODEL](THREAT_MODEL.md)) |
| Implementation | [services/api/src/docentric_copilot/api/app.py](../services/api/src/docentric_copilot/api/app.py) and `api/routes/` |

The examples below were produced by calling a locally running application with the mock provider. IDs,
digests and timestamps vary per run; long objects are abridged where marked and remain valid JSON.

## 1. Conventions

### 1.1 Error envelope

Every expected failure is a `CopilotError` and returns the same shape:

```json
{
  "error": {
    "code": "target_unsupported",
    "message": "The Docentric AX compiler is not available: ...",
    "details": { "target": "docentric-ax" }
  }
}
```

`details` is optional and omitted when empty. `code` is the stable machine code. It is usually the
error-class code (`input_invalid`, `not_found`, …), but parser/security failures propagate their
diagnostic code (`DDSP001`, `XML001`, …), so clients must not assume a closed set of envelope codes.
The `message` is human-readable and may change; match on `code` and HTTP status.

| HTTP | `code` (examples) | Raised when |
| --- | --- | --- |
| 400 | `input_invalid`, `security_violation`, `DDSP002`, `DDSP008`, `DDSP011`, `XML001`, `XML002`, `XML003`, `XML004`, `ir_version_unsupported` | Malformed request/IR, corrupt archive, empty archive, rejected DTD/XML construct, IR version unknown |
| 402 | `budget_exceeded` | Worst-case generation cost exceeds the configured budget |
| 404 | `not_found` | Source, template version, job or job id does not exist |
| 409 | `target_unsupported` | Compilation target is unavailable/unverified (`docentric-ax`) |
| 410 | `artifact_unavailable` | Artifact id unknown, expired or its file missing |
| 415 | `input_unsupported`, `DDSP001`, `DDSP002`, `DDSP008` | Unsupported upload extension, too-large file, unknown container, no XML |
| 422 | `validation_failed`, `compilation_failed`, `input_invalid` | IR fails V1–V3 where compilation is required; request model validation |
| 502 | `provider_error`, `provider_timeout`, `provider_bad_response`, `provider_invalid_output`, `model_required`, `plan_invalid` | Provider transport/response failures |
| 503 | `provider_not_configured` | Provider unknown or missing API key |
| 500 | `internal_error` | Unexpected exception; details are intentionally withheld |

A diagnostic code can surface with more than one status depending on the code path: for example
`DDSP002` is `415` for an unclassifiable container but `400` for a corrupt ZIP that began with the PK
magic, and `DDSP008` is `415` for a container with no XML documents but `400` for an empty container.
Match on the HTTP status together with the code; do not assume a one-to-one mapping.

FastAPI request-model failures bypass the `CopilotError` handler and are converted explicitly to
`422 input_invalid` with per-field errors:

```json
{
  "error": {
    "code": "input_invalid",
    "message": "Request body failed validation",
    "details": {
      "errors": [{ "location": "body.prompt", "message": "String should have at least 3 characters", "type": "string_too_short" }]
    }
  }
}
```

An unhandled exception logs a traceback server-side and returns
`{"error": {"code": "internal_error", "message": "An unexpected error occurred"}}`.

### 1.2 Identifiers

Opaque, URL-safe, prefixed by resource kind: `src_…` (source), `job_…` (job), `art_…` (artifact),
`tpl_…` (template). Ids are 20 random base36 characters after the prefix. They are **not** secrets and
are not authenticated.

### 1.3 Request limits

| Limit | Value | Source |
| --- | --- | --- |
| Upload extensions | `.ddsp`, `.xml`, `.xsd`, `.zip` (case-insensitive) | `routes/sources.py` |
| Upload bytes | `DC_MAX_DDSP_BYTES` (default 10 MiB) | `config.Limits` |
| Requirement / instruction | 3–5,000 / 3–2,000 chars | `schemas.py` |
| Inline IR | a JSON object; model-validated (`extra="forbid"`) | `template_ir` |
| Model id | ≤ 120 chars | `schemas.py` |
| CORS | configured origins only (`DC_CORS_ORIGINS`), `GET, POST, OPTIONS`, request header `Content-Type`, exposed `Content-Disposition`, `X-Artifact-Digest` | `api/app.py` |

There is no pagination, rate limiting, idempotency key or authentication in this build.

### 1.4 Request/response models

All bodies use the pydantic models in
[services/api/src/docentric_copilot/api/schemas.py](../services/api/src/docentric_copilot/api/schemas.py).
`extra="forbid"` is set on every request model: unknown keys are rejected with `422`.

## 2. Sources

### 2.1 `POST /api/v1/sources` — upload a DDSP package

`multipart/form-data` with a single field `file`. The parser treats the bytes as untrusted and applies
the limits in [DDSP_COMPATIBILITY](DDSP_COMPATIBILITY.md).

**Response `201` — `SourceView`**

```json
{
  "source_id": "src_yw5fjev8lv21ob5pofwk",
  "filename": "sales-quotation.ddsp",
  "schema_id": "sales_quotation",
  "sections": ["MainData", "GeneralData", "Parameters"],
  "stats": {
    "node_count": 34,
    "scalar_count": 28,
    "collection_count": 1,
    "attribute_count": 0,
    "max_depth": 3
  },
  "sample_data_available": true,
  "diagnostics": [
    {
      "code": "INFO002",
      "severity": "info",
      "message": "ZIP container with 3 entries",
      "location": null
    },
    {
      "code": "INFO002",
      "severity": "info",
      "message": "Sample data loaded from 'data/sample.xml'",
      "location": "data/sample.xml"
    }
  ],
```

Errors: `415 input_unsupported` for a disallowed extension; `415 DDSP001` for an oversized file;

archive; `415 DDSP002`/`DDSP008` for an unclassifiable container or a container with no XML documents;
`400 XML001`–`XML004` for hostile or oversized XML; `400` with a diagnostic code when no usable schema
can be derived.

## 3. Templates

### 3.1 `POST /api/v1/templates/plan` — requirement → IR

**Request**

```json
{
  "source_id": "src_yw5fjev8lv21ob5pofwk",
  "prompt": "Create a professional sales quotation for the customer.",
  "provider": "mock",
  "model": null,
  "routing": "explicit",
  "compact_ir": null,
  "design_style": "modern",
  "target": "generic-docx",
  "options": {
    "language": "en",
    "strict_validation": true,
    "max_generation_cost_usd": 0.5,
    "max_repair_attempts": 1
  }
}
```

| Field | Required | Notes |
| --- | --- | --- |
| `source_id` | yes | 4–60 chars; must exist |
| `prompt` | yes | 3–5,000 chars |
| `provider` | no | default `mock`; `openai`, `anthropic`, `gemini` require configuration. Ignored when `routing` is `auto` |
| `model` | no | provider default if omitted. Ignored when `routing` is `auto` |
| `routing` | no | `explicit` (default) uses the request provider/model; `auto` classifies the brief, routes against the configured providers and returns an execution trace |
| `compact_ir` | no | `null` (default) auto-enables the compact wire format for Gemini 3.x; `true` forces it for any provider; `false` forces the full Template IR response |
| `design_style` | no | `modern` (default), `classic`, `minimal` |
| `target` | no | `generic-docx` (default) or `docentric-ax`; the IR records the request, compilation still enforces the gate |
| `options.language` | no | `^[a-z]{2}(-[A-Z]{2})?$` |
| `options.strict_validation` | no | default `true`: reject the plan when V1–V3 do not pass |
| `options.max_generation_cost_usd` | no | per-request cost ceiling, range-validated and passed to the gateway as the pre-flight budget; defaults to `DC_LLM_MAX_GENERATION_COST_USD` (0.50) when omitted |

### 3.2 `POST /api/v1/templates/validate` — validate an IR

**Request**

```json
{
  "source_id": "src_yw5fjev8lv21ob5pofwk",
  "template_id": "tpl_8ldpclf68nfrxtlan2r4",
  "version": 1,
  "ir": null,
  "target": "generic-docx"
}
```

Resolution precedence: `ir` (inline) wins over `template_id`; if neither is provided the request fails
with `400 input_invalid`. `version` defaults to the template's current version. The document's
`target` is replaced by the request `target` before validation.

**Response `200` — `ValidateResponse`**

```json
{
  "validation": {
    "structural": "passed",
    "semantic": "passed",
    "logical": "passed",
    "visual": "passed",
    "docentric_compatibility": "not_tested"
  },
  "overall": "passed_unverified_compatibility",
  "report": {
    "schema_id": "sales_quotation",
    "target": "generic-docx",
    "ir_digest": "9f8d8ad173de468783ce0ecc785394985f5930b987cabeaa9e21e5f4c7a967b4",
    "checks": []
  }
}
```

`visual` is `skipped` when the source has no sample data. Validation does **not** return an error for a
failing report; it returns `200` with statuses. Only malformed IR or a missing resource produces an
error status.

| --- | --- |

```json
        "name": "Main",
        "body": [
          {
            "kind": "paragraph",
```

## 5. Artifacts

Artifacts are written by plan (IR, mapping, validation JSON/HTML, preview) and compile (DOCX,
validation JSON/HTML). See [ARCHITECTURE §5.5](ARCHITECTURE.md#55-artifacts-and-storage).

| Endpoint | Behaviour |
| --- | --- |
| `GET /api/v1/artifacts/{artifact_id}` | File download with the artifact's media type and filename. Headers: `X-Content-Type-Options: nosniff`, `Cache-Control: private, max-age=0, no-store`, `X-Artifact-Digest: <sha256 of the served bytes>` |
| `GET /api/v1/artifacts/{artifact_id}/view` | Inline view for `text/html` artifacts; for any other media type returns `415` with a small HTML page (not the JSON envelope) |

**Lifecycle**

1. Created on a successful plan/compile with `expires_at = now + DC_ARTIFACT_TTL_SECONDS`
   (default 3600 s, minimum 60).
2. Rows and files are removed lazily: reading an expired or missing artifact deletes it and raises
   `ArtifactError` (`410 artifact_unavailable`). `purge_expired()` runs at application startup and
   deletes expired artifacts and sources older than the TTL.
3. There is no renewal, copy or list endpoint. Persist what you need before the TTL elapses; the
   versioned IR in the database does not expire, but its exported artifacts do.
4. Unknown, expired and deleted ids are indistinguishable: all return `410`.

## 6. OpenAPI

The live OpenAPI 3.1 document is served at `GET /openapi.json`; Swagger UI at `/docs`; ReDoc at
`/redoc`. It is generated from the FastAPI routes and the pydantic models, so it is the authoritative
schema for request/response shapes at a given revision. A static export is committed at
[docs/openapi.json](openapi.json) (28 paths) and regenerated by `make openapi`
(`scripts/export_openapi.py`); CI fails if it is stale.

## 7. Client notes

### 7.1 Reference web client

The Next.js workspace in `apps/web` is the reference client. It uses this API only:

- base URL from `NEXT_PUBLIC_API_BASE_URL` (default `http://localhost:8000`, no trailing slash),
  inlined at build time;
- CORS: the API default allows `http://localhost:3000` only (`DC_CORS_ORIGINS` to change it);
- the preview is shown in a sandboxed iframe (`sandbox=""`), not injected into the workspace DOM;
- DOCX and report artifacts are downloaded from `/api/v1/artifacts/{id}`;
- provider errors, `validation_failed`, `target_unsupported` and network failures are surfaced using
  the error envelope's `code` and `message`.

The UI is English-only and has no browser test suite committed; see [TEST_PLAN](TEST_PLAN.md).

### 7.2 General client guidance

- Poll `GET /api/v1/jobs/{id}` only if you need the job record; plan/compile/revise calls are
  synchronous and already return the result.
- Treat `validation.docentric_compatibility == "not_tested"` as the expected value. A client that
  requires a compatibility assertion must fail, not assume success.
- `validation.visual == "skipped"` means "not enough information", not "layout fine".
- A `200` validation response can still contain failing statuses; `can_compile` is not exposed as a
  field, so check `overall` (or the V1–V3 statuses).
- `digest` values are SHA-256 of the artifact bytes; the IR digest is SHA-256 of canonical IR JSON.

## 8. Reference inspection (read-only)

Reference endpoints never execute macros, expressions or Docentric code, never write the inspected
template, and always report `runtime_compatibility: "not_tested"`.

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `POST` | `/api/v1/reference/inspect` | Inventory, content controls and REF-02 metadata resolution |
| `POST` | `/api/v1/reference/graph` | Read-only ReferenceGraph and optional reference projection |
| `POST` | `/api/v1/reference/d365` | Embedded D365 schema extraction and canonical binding resolution |
| `POST` | `/api/v1/reference/diff` | Structural and semantic reference diff |

### 8.1 `POST /api/v1/reference/d365`

`?path=` query parameter inside `DC_REFERENCE_CORPUS_ROOTS`. A package with several DOCX templates is
rejected with `415 reference_d365_multiple_documents` rather than partially analysed. A malformed
container or XML document returns `400` with a stable code; a malformed `ProjectData` part inside an

### 8.2 `POST /api/v1/reference/import-ir`

Multipart `file` (`.docx`, `.zip`, `.axpp`) with an optional `ddsp` part, or `?path=` inside a
configured corpus root. Query `allow_unsupported` defaults to `false`. The response is
`ReferenceIRImport`:

```json
{
  "import_version": "1.0",
  "reference_version": "1.0",
  "runtime_compatibility": "not_tested",
  "target": "generic-docx",
  "source_name": "template.docx",
  "source_sha256": "<sha256>",
  "allow_unsupported": false,
  "ir": {"kind": "document", "ir_version": "1.0", "target": "generic-docx"},
  "skipped": [],
  "provenance": [{"ir_path": "sections[0].body[0].runs[0]", "node_kind": "field"}],
  "validation": {"statuses": {"structural": "passed", "semantic": "passed", "logical": "passed", "visual": "skipped", "docentric_compatibility": "not_tested"}, "can_compile": true},
  "summary": {"references": 1, "imported": 1, "skipped": 0}
}
```

Strict mode returns HTTP `422` with `reference_import_blocked` and the complete `skipped[]` when
anything is unsupported, ambiguous or unresolved. If no construct can be imported safely it returns
HTTP `422` with `reference_import_empty`. The target is always `generic-docx`; the endpoint never
enables `docentric-ax` and never claims Docentric AX runtime compatibility. See
[REFERENCE_TEMPLATES §27](REFERENCE_TEMPLATES.md#27--safe-reference--generic-template-ir-import).

### 8.3 `POST /api/v1/reference/reports`

Runs the reference analysis server-side and persists the serialized envelope in local SQLite under
the artifact TTL (default 3600 seconds). Query `kind` is `inspection` (report + graph, default),
`graph` or `diff` (multipart `left`/`right` or `left_path`/`right_path`). No source template bytes
are stored. The response contains `id`, `kind`, `schema_version`, `created_at`, `expires_at`,
`source_name`, `source_sha256`, `report`, `graph`, `diff`, `warnings` and
`runtime_compatibility: "not_tested"`.

`GET /api/v1/reference/reports/{id}` reopens the same envelope; missing or expired ids return HTTP
`404` with `reference_report_not_found`. `GET .../export?format=json|html` returns the complete JSON
or a self-contained, HTML-escaped export suitable for review. See
[REFERENCE_TEMPLATES §29](REFERENCE_TEMPLATES.md#29--persistence-reopen-and-export).
