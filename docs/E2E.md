# Browser E2E — Reference Inspector (V012-08)

The v0.12 suite drives the real FastAPI app and the built Next.js app with
Playwright/Chromium. It uses only local synthetic fixtures: no API key, no
provider call, no network dependency and no private D365 corpus.

| Field | Value |
| --- | --- |
| Suite | [tests/e2e/](../tests/e2e/) |
| Runner | Python Playwright, pinned `playwright==1.64.1` in `pyproject.toml` |
| Browser | Chromium installed by that Playwright version (`python -m playwright install chromium`) |
| CI | `E2E · Playwright Reference Inspector` job in [ci.yml](../.github/workflows/ci.yml) |
| Artifacts | `test-results/e2e/` (screenshots, traces, server logs, browser version) |

## What it covers

Happy path (TZ §7 steps 1–8):

1. open `/reference`;
2. upload a generated synthetic DOCX;
3. inspect and persist the report;
4. open Overview, Controls, Graph and Diff (Diff compares the document with
   itself, a deterministic no-change result);
5. confirm the saved report id;
6. reload the page;
7. reopen the report by `?id=`;
8. export JSON and HTML and validate both payloads.

Negative paths:

- invalid DOCX / non-ZIP archive;
- oversized upload rejected before the API call (the UI reads the limit from
  `/api/v1/capabilities`);
- missing/invalid report id;
- simulated report-store failure (`500 storage_unavailable`);
- an unsupported control construct stays visible in the Controls table instead
  of crashing the page.

The suite also fails on an uncaught `pageerror`. It does not treat a warning
banner as an inspection failure.

## Run it locally

```bash
# once per checkout (the E2E fixture builds the app if .next is missing)
npm --prefix apps/web ci
.venv/bin/pytest tests/e2e --e2e -q
```

The fixture starts the API and web app on `127.0.0.1:8100` and
`127.0.0.1:3100`, waits for readiness, and stops both process groups after the
session. The Next.js proxy target is compiled into the build, so the fixture
rebuilds when the target changes; `DC_E2E_FORCE_BUILD=1` forces it. If
`.tools/pw-browsers` exists it is used as the Playwright browser cache;
otherwise the normal Playwright cache applies.

Useful overrides:

| Variable | Meaning |
| --- | --- |
| `DC_E2E_API_PORT`, `DC_E2E_WEB_PORT` | Fixed free ports (defaults `8100`, `3100`) |
| `DC_E2E_BASE_URL` | Use an already running web app instead of starting one |
| `DC_E2E_API_URL` | API URL for the external web app |
| `DC_E2E_FORCE_BUILD=1` | Rebuild the Next.js app even if `.next` exists |
| `DC_E2E_TIMEOUT` | Server readiness timeout in seconds (default `180`) |
| `DC_E2E_HEADED=1` | Launch Chromium headed for debugging |
| `DC_E2E_ARTIFACT_PROBE=1` | Run the intentional failing probe |

One test file:

```bash
.venv/bin/pytest tests/e2e/test_reference_e2e.py::test_reference_happy_path_upload_save_reload_and_export --e2e -q
```

## Artifacts and failure proof

Every failing test writes, under `test-results/e2e/<nodeid>/`:

- `failure.png` — full-page screenshot;
- `trace.zip` — Playwright trace with snapshots and sources;
- `page-errors.txt` — uncaught page errors.

The optional probe intentionally fails and is run by CI after the main suite:

```bash
DC_E2E_ARTIFACT_PROBE=1 .venv/bin/pytest tests/e2e/test_artifact_probe.py --e2e -q || true
test -f test-results/e2e/*artifact_probe*/failure.png
test -f test-results/e2e/*artifact_probe*/trace.zip
```

The CI job uploads the whole directory with `if: always()`.

## Stable selectors

Critical controls expose `data-testid` attributes, so tests do not depend on
copy or CSS classes:

| Test id | Element |
| --- | --- |
| `reference-template-file-input` | Template upload input |
| `reference-inspect-button` | Inspect reference |
| `reference-saved-report` | Saved report badge (contains the id) |
| `reference-export-format` / `reference-export-button` | Export controls |
| `reference-tab-overview` / `-controls` / `-graph` / `-diff` | Tabs |
| `reference-diff-left-input` / `-right-input` / `-compare` | Diff controls |

Accessible roles and labels remain the primary selectors where they are
unambiguous (heading, alert, table cell).

## Determinism and scope

- The reference inspector is static analysis; the suite clears provider keys in
  the server environment so a stray LLM call cannot happen.
- Fixtures are generated by `tests/reference_fixtures.py`; no licensed or
  private document is committed.
- Chromium only. The suite is a functional UI regression, not a pixel-fidelity
  visual test; LibreOffice/Poppler rendering is covered separately by the
  visual-diff CI job (V012-07) and is labelled as LibreOffice rendering, not
  Word fidelity.
- Responsive viewport checks for `/reference` are part of the v0.12 release
  documentation status (see the release evidence), not a claim that mobile is
  supported.
