## Context

REF-03 made reference material queryable as a read-only graph, but two questions remained:

1. **What changed between two references?** Real-world families such as a base template and a
   reshaped variant, an older and a newer Designer version, or a tax-included and tax-excluded
   report differ along several axes at once. Comparing raw document hashes creates false "new
   versions"; comparing only visible text hides binding and scope changes. A comparison needs
   stable keys, explicit added/removed/changed items, and a separation between structural
   placement and semantic binding.
2. **Did a generated plan reproduce the reference's semantic patterns?** The existing semantic
   benchmark uses hand-authored business prompts and schemas. It does not say whether a plan uses
   the Field/List/If/Image/Label patterns and bindings observed in an actual reference template.

Both concerns touch licensed material. The Docentric archive must not be committed, and reports
derived from it may contain vendor text and business-shaped metadata. The comparison and evaluation
therefore have to work at runtime against the ignored local corpus while keeping committed fixtures
entirely synthetic. They must also keep the existing contracts intact: Template IR 1.0, the V5
`not_tested` status, and the fail-closed `target=docentric-ax` HTTP `409`.

## Decision

### REF-04 — `ReferenceDiff` v1.0

Introduce `docentric_copilot.reference.diff` with a deterministic, read-only comparison contract:

- Inputs may be two `ReferenceGraph`s, two inspection bundles, two reports, or two reference paths.
  Path inputs use the existing bounded inspector and optional `--ddsp` schema.
- Stable keys are derived from part, ProjectData element id, schema path, source name and control
  identity. Document SHA-256 and absolute paths are deliberately excluded so a renamed copy or a
  changed binding does not relocate every item.
- Items cover `control`, `element`, `binding`, `source` and `schema_field`. Each changed item carries
  before/after snapshots of kind, binding path, status, part, paragraph, source, data type and
  collection flag.
- **Structural** changes are presence changes (added/removed) and location-only changes (part or
  paragraph). **Semantic** changes are binding path, resolution status, element kind, source and
  data type/collection. A change with both aspects is classified semantic and its `fields` list still
  names the location change.
- The report includes total and per-dimension counts, per-kind counts, part and count deltas,
  coverage deltas (edge and control resolution), unresolved counts plus the stable keys that
  appeared or disappeared, status transitions, ordering and a `diff_digest`.
- Ordering is canonical: item kind, change type, stable key, then dimension.
- Surface: Python `build_reference_diff` / `diff_reference_graphs` / `diff_reference_paths`;
  CLI `docentric-copilot reference diff LEFT RIGHT --json OUT [--ddsp PATH]`; HTTP
  `POST /api/v1/reference/diff` with two multipart files or two corpus-confined paths.

### REF-05 — reference-based evaluation

Introduce `benchmarks/reference_evaluation.py`, `benchmarks/reference_cases.json` and synthetic
fixtures under `benchmarks/fixtures/reference/`:

- The committed gold set has eight cases covering Field (scalar), List (collection), If
  (condition), Image and Label (text) patterns, including header/footer and mixed cases. All DOCX
  and DDSP fixtures are generated by `benchmarks/reference_fixtures.py`; no vendor material is used.
- The evaluator maps inspected reference controls/elements to expected concepts and scores a
  generated or supplied plan with precision, recall, coverage, F1 and type/context correctness.
  `valid_template_rate` (validation + compilation) is reported separately and is never folded into
  the semantic metrics.
- `--cases` uses the committed synthetic set. `--reference PATH` inspects a DOCX/AXPP at runtime and
  derives the expectation inventory from it; `--ddsp` supplies the schema and either an existing
  `--plan` or a freshly generated plan is scored.
- The default provider is the deterministic `mock`, so CI needs no paid calls. A non-mock provider
  requires explicit `--allow-paid`. Cost is three-valued (`verified`, `estimated`, `unavailable`);
  mock runs are verified at zero and unknown is never rendered as `$0.00`.
- Reports are written as JSON, CSV and self-contained HTML with sample size, provenance
  (`synthetic` vs `local-corpus`), pattern counts, an error taxonomy and cost status. Corpus-mode
  reports are runtime-only and must stay in ignored directories.
- Real AX DDSP contracts expose XSD attributes as `@Name` paths, while Template IR 1.0 forbids raw
  XPath/attribute syntax. For evaluation only, an IR-safe schema view renames those segments on both
  the schema and the reference concepts. Role, type, collection and context are unchanged; the
  normalization is recorded in the report. Template IR, the reference inspector's graph and all
  compilers are untouched.

The existing AX gate remains unchanged: no diff or evaluation path can enable native output,
`target=docentric-ax` still returns `409`, and V5 stays `not_tested`.

## Consequences

Positive:

- Reference families can be compared with explicit provenance, stable keys and no false version
  churn from file renames or document hashes.
- Structural movement and semantic binding changes are separately reviewable.
- The synthetic gold set makes reference-pattern regressions testable in public CI without the
  corpus, while the same evaluator can consume a real reference privately at runtime.
- Precision/recall/coverage and technical validity stay separate, so a valid template cannot hide
  a wrong binding.
- The evaluation report never needs to commit corpus paths or content.

Negative and open:

- The synthetic gold set is small (eight cases, 41 expected concepts) and is not a population sample
  or a model-quality claim; the mock provider is a deterministic baseline.
- The reference-mode path normalization changes path spelling for evaluation. It is documented, but
  it means a corpus-mode score measures pattern reproduction under IR-safe names, not native AX
  XPath execution.
- AXPP references with several DOCX documents are evaluated as one concept inventory; per-document
  grouping is future work.
- Diff keys cannot distinguish two controls or elements that share every available identity; a
  deterministic occurrence suffix is used, and such duplicates remain visible.
- D365 documents without a standalone DDSP still have no schema fields to compare or evaluate.

## Alternatives considered

- **Compare raw files or report digests only.** Rejected: detects change but cannot classify it, and
  renamed identical content produces false versions.
- **Use node ids from ReferenceGraph directly.** Rejected: they contain the document SHA-256, so
  every content change relocates every key.
- **Fold valid-template rate into precision.** Rejected: contradicts the existing semantic benchmark
  and hides semantically wrong but compilable output.
- **Evaluate directly from the reference without a gold set.** Rejected as the only mode: it is
  circular. The evaluator therefore uses hand-authored synthetic gold for `--cases` and also checks
  that the reference-derived inventory agrees with it.
- **Publish a sanitised corpus report.** Rejected: counts are enough for the public record; real
  template content and business-shaped metadata stay private.
- **Relax Template IR to accept `@` paths.** Rejected: requires a migration ADR and weakens the
  validated compiler contract.

## Follow-up

- REF-06: inspector UI and storage workflow over `ReferenceDocument` and the diff/evaluation reports.
  It must display evidence, not compile or claim runtime compatibility.
- REF-07: licensed Docentric runtime testing before any import or native-output decision.
- Grow the human-reviewed gold set toward the specification's target and add a calibration/holdout
  split before making model-quality or cost claims.
- Consider per-document diff scoping and path normalization as explicit graph metadata if future
  consumers need native AX paths in evaluation output.
